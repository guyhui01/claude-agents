# Skill — Architecture de l'Information
> Certifications : UXQB CPUX-F · IDF

## Objectif
Organiser et structurer le contenu d'un produit pour que les utilisateurs trouvent l'information facilement.

## Techniques
- **Card sorting** (ouvert / fermé / hybride) : identifier les modèles mentaux utilisateurs
- **Tree testing** : valider la navigation proposée sans interface visuelle
- **Sitemap** : hiérarchie des pages et contenus
- **Navigation patterns** : barre latérale, tabs, breadcrumbs, mega-menu

## Livrables
- Résultats card sorting (dendrogramme, matrice de similarité)
- Score tree testing (succès direct, succès indirect, échec)
- Sitemap annoté
- Recommandations de navigation

## Outils recommandés
Optimal Workshop · Maze · FigJam · Miro

## Format de sortie
Précise : type de produit · volume de contenu · public cible · résultats research existants

## Sources
- **Louis Rosenfeld, Peter Morville & Jorge Arango** — *Information Architecture for the Web and Beyond* (O'Reilly, 4e éd. 2015) — ouvrage de référence (« polar bear book »)
- **Donna Spencer** — *Card Sorting: Designing Usable Categories* (Rosenfeld Media, 2009) — méthode du card sorting
- **Dave O'Brien / Optimal Workshop** — formalisation du *tree testing* (validation de navigation sans UI)
- **Jakob Nielsen** — *Mega Menus Work Well for Site Navigation* (NN/g) — patterns de navigation

## Anti-patterns
- Calquer l'AI sur l'organigramme interne plutôt que sur les modèles mentaux des utilisateurs
- Sitemap conçu sans validation (ni card sorting ni tree testing) = hypothèse non testée
- Sur-imbrication : profondeur > 3 niveaux qui dégrade la retrouvabilité
- Libellés de menu jargon métier au lieu du vocabulaire utilisateur
- Card sorting avec un échantillon trop faible (< 15 participants pour une analyse fiable)

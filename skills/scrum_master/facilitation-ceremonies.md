# Skill — Facilitation des Cérémonies Scrum
> Certifications : PSM I/II/III · CSM · A-CSM · ICAgile ICP-ATF

## Objectif
Faciliter les cérémonies Scrum avec excellence pour maximiser la valeur livrée et l'apprentissage de l'équipe.

## Les 5 événements Scrum et leur facilitation

### Sprint Planning
```
Durée     : 2h max pour un sprint de 2 semaines
Objectif  : Définir le Sprint Goal + sélectionner les PBIs
Inputs    : Product Backlog raffiné, vélocité de l'équipe, capacité du sprint

Structure :
  Part 1 (1h) — QUOI : PO présente les items à plus haute valeur
    → Question clé : "Que peut livrer l'équipe ce sprint ?"
    → Sprint Goal co-construit avec PO + équipe

  Part 2 (1h) — COMMENT : Équipe décompose en tâches
    → Questions clés : "Comment atteindre le Sprint Goal ?"
    → Estimation des tâches (heures ou story points)
    → Capacité : (nb de jours × nb de devs) - congés - réunions

Outputs   : Sprint Goal validé, Sprint Backlog, engagement de l'équipe
```

### Daily Scrum (Daily Stand-up)
```
Durée    : 15 min max, même heure, même lieu
Objectif : Synchronisation quotidienne vers le Sprint Goal

3 questions classiques (format minimal) :
  1. Qu'ai-je accompli hier pour atteindre le Sprint Goal ?
  2. Que vais-je faire aujourd'hui pour atteindre le Sprint Goal ?
  3. Quels obstacles bloquent ma progression ?

Formats alternatifs (2026) :
  → Walk the board (gauche → droite sur le kanban board)
  → Réponse par item du Sprint Backlog (plutôt que par personne)

SM Role : Faciliter, protéger le timebox, noter les impediments
```

### Sprint Review
```
Durée    : 1h max pour 2 semaines
Objectif : Inspecter l'Increment + adapter le Product Backlog

Agenda :
  1. Sprint Goal atteint ? (5 min)
  2. Démo des fonctionnalités Done (30 min)
  3. Feedback des parties prenantes (15 min)
  4. Mise à jour du backlog (10 min)

SM Role : Faciliter la démo, créer un espace de feedback sécurisé
```

### Sprint Retrospective
```
Durée    : 1h30 max pour 2 semaines
Objectif : Amélioration continue des pratiques de l'équipe

Formats populaires :
  - Start/Stop/Continue
  - 4Ls (Liked, Learned, Lacked, Longed for)
  - Mad/Sad/Glad
  - Sailboat (vents = forces, ancres = obstacles)
  - Timeline (revisiter le sprint jour par jour)

Structure (tout format) :
  1. Check-in (5 min) — température de l'équipe
  2. Collecte de données (20 min) — ce qui s'est passé
  3. Insights (20 min) — patterns, causes racines
  4. Actions (15 min) — 1-3 actions SMART pour le prochain sprint
  5. Check-out (5 min) — comment on part ?

Règle d'or : 1 action de retro par sprint, pas 10
```

### Backlog Refinement
```
Durée    : Max 10% du sprint (2h/sprint de 2 semaines)
Objectif : Préparer le backlog pour le prochain Sprint Planning

Activités :
  - Clarifier les user stories ambiguës
  - Découper les épics trop grosses (splitting)
  - Estimer les nouveaux items
  - Ordonner par valeur et dépendances

SM Role : Faciliter les discussions, timeboxer, challenger les critères d'acceptation
```

## Livrables
- Plan de facilitation (agenda + objectifs) par cérémonie
- Compte-rendu Sprint Review (1 page)
- Action items de rétro tracés dans le backlog
- Vélocité et burndown chart

## Format de sortie
Précise : cérémonie · taille de l'équipe · problèmes observés dans l'équipe · format préféré (remote/présentiel) · niveau de maturité Scrum

# Skill — Capabilities & Large Solution (SAFe)
> Certifications : SAFe POPM 6 · SAFe LPM

## Objectif
Gérer les Capabilities au niveau Large Solution, entre les Epics Portfolio et les Features d'ART.

## Hiérarchie SAFe complète
```
Portfolio Level  : Epics (Strategic Themes, Portfolio Vision)
Large Solution   : Capabilities (cross-ART, nécessitent plusieurs ARTs)
Program Level    : Features (un seul ART, 1 PI)
Team Level       : Stories (une équipe, 1 sprint)
```

## Capability vs. Feature
| Critère | Capability | Feature |
|---|---|---|
| Périmètre | Plusieurs ARTs | Un seul ART |
| Durée | Plusieurs PIs | 1 PI maximum |
| Responsable | Solution Manager | Product Manager |
| Acceptance | Solution Demo | System Demo |

## Rédiger une Capability
- Format : "Le système [capability] afin de [bénéfice solution]"
- Benefit Hypothesis : valeur attendue si la capability est livrée
- Leading Indicators : comment mesurer avant la fin ?
- Décomposition en Features par ART

## Solution Backlog
- Alimenté par les Epics Portfolio
- Priorisé par WSJF au niveau Solution
- Synchronisé lors du Pre-PI Planning Solution

## Livrables
- Capabilities rédigées et décomposées en Features
- Solution Backlog priorisé
- Matrice Capability × ART (ownership)
- Dépendances inter-ARTs documentées sur le Program Board

## Format de sortie
Précise : nombre d'ARTs · périmètre solution · niveau de maturité Large Solution · outils

# Skill Scrum — Gestion & Priorisation du Backlog

## Structure
Vision Produit → Product Goal → Epics → Features → User Stories → Tâches

## Priorisation MoSCoW
| Niveau | Signification | Action |
|---|---|---|
| **M** Must Have | Indispensable | Sprint en cours |
| **S** Should Have | Important | Prochain sprint |
| **C** Could Have | Souhaitable | Backlog moyen terme |
| **W** Won't Have | Exclu | Backlog long terme |

## Planning Poker — Fibonacci
1 — 2 — 3 — 5 — 8 — 13 — 21 — ? (trop complexe → découper)

## Story Mapping
1. Identifier les activités utilisateur (axe horizontal)
2. Décomposer en tâches (axe vertical)
3. Définir le MVP (ligne de découpe)
4. Constituer les releases

## Backlog Grooming (Refinement)
- Fréquence : 1 fois par sprint (milieu de sprint)
- Durée : max 10% du sprint
- Participants : PO + équipe + Scrum Master
- Objectif : préparer les US pour le prochain Sprint Planning

## Checklist santé du backlog
- [ ] Ordonné par priorité
- [ ] 2 sprints d'avance avec DOR validée
- [ ] US obsolètes archivées
- [ ] Dépendances tracées
- [ ] Dernière revue : [date]

## Template Roadmap trimestrielle
```
Q[X] — Product Goal : [objectif]

Sprint N   | [Feature 1]  | [Feature 2]  |
Sprint N+1 | [Feature 3]  | [Feature 4]  |
Sprint N+2 | [Feature 5]  | Dette tech   |

KPIs cibles : [métrique 1] / [métrique 2]
```

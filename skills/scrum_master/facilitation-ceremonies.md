# Skill — Facilitating Scrum Events
> Certifications: PSM I/II/III · CSM · A-CSM · ICAgile ICP-ATF

## Objective
Facilitate Scrum events with excellence to maximize delivered value and team learning.

## The 5 Scrum events and their facilitation

### Sprint Planning
```
Duration  : 2h max for a 2-week sprint
Goal      : Define the Sprint Goal + select the PBIs
Inputs    : Refined Product Backlog, team velocity, sprint capacity

Structure:
  Part 1 (1h) — WHAT: PO presents the highest-value items
    → Key question: "What can the team deliver this sprint?"
    → Sprint Goal co-built with PO + team

  Part 2 (1h) — HOW: Team breaks down into tasks
    → Key questions: "How do we reach the Sprint Goal?"
    → Task estimation (hours or story points)
    → Capacity: (number of days × number of devs) - time off - meetings

Outputs   : Validated Sprint Goal, Sprint Backlog, team commitment
```

### Daily Scrum (Daily Stand-up)
```
Duration : 15 min max, same time, same place
Goal     : Daily synchronization toward the Sprint Goal

3 classic questions (minimal format):
  1. What did I accomplish yesterday toward the Sprint Goal?
  2. What will I do today toward the Sprint Goal?
  3. What obstacles are blocking my progress?

Alternative formats (2026):
  → Walk the board (left → right on the kanban board)
  → Answer per Sprint Backlog item (rather than per person)

SM role: Facilitate, protect the timebox, note impediments
```

### Sprint Review
```
Duration : 1h max for 2 weeks
Goal     : Inspect the Increment + adapt the Product Backlog

Agenda:
  1. Sprint Goal met? (5 min)
  2. Demo of the Done features (30 min)
  3. Stakeholder feedback (15 min)
  4. Backlog update (10 min)

SM role: Facilitate the demo, create a safe feedback space
```

### Sprint Retrospective
```
Duration : 1h30 max for 2 weeks
Goal     : Continuous improvement of the team's practices

Popular formats:
  - Start/Stop/Continue
  - 4Ls (Liked, Learned, Lacked, Longed for)
  - Mad/Sad/Glad
  - Sailboat (winds = strengths, anchors = obstacles)
  - Timeline (revisit the sprint day by day)

Structure (any format):
  1. Check-in (5 min) — team temperature
  2. Data gathering (20 min) — what happened
  3. Insights (20 min) — patterns, root causes
  4. Actions (15 min) — 1-3 SMART actions for the next sprint
  5. Check-out (5 min) — how do we leave?

Golden rule: 1 retro action per sprint, not 10
```

### Backlog Refinement
```
Duration : Max 10% of the sprint (2h for a 2-week sprint)
Goal     : Prepare the backlog for the next Sprint Planning

Activities:
  - Clarify ambiguous user stories
  - Split epics that are too big (splitting)
  - Estimate new items
  - Order by value and dependencies

SM role: Facilitate discussions, timebox, challenge the acceptance criteria
```

## Deliverables
- Facilitation plan (agenda + goals) per event
- Sprint Review notes (1 page)
- Retro action items tracked in the backlog
- Velocity and burndown chart

## Output format
Specify: event · team size · problems observed in the team · preferred format (remote/on-site) · Scrum maturity level

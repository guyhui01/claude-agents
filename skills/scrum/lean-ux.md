# Skill — Lean UX & Design Thinking embedded in the sprint

> Certification: PSPO II · PSU-I
> Agent: AGENT-PO-SCRUM.md

## Objective
Embed Lean UX and Design Thinking practices into the Scrum cycle to reduce development waste and validate product hypotheses before coding.

## When to use this skill
- Before writing a User Story on an uncertain feature
- During a Dual Track Discovery / Delivery
- To challenge product assumptions with real user data

## Lean UX practices to master

### 1. Problem Statement
```
[User] needs a way to [need/goal]
because [insight — why this need exists]
```

### 2. Value Hypothesis
```
We believe that [feature]
will let [user]
achieve [expected outcome]
We will know it when [validation metric]
```

### 3. Minimum Viable Experiment (MVE)
- Identify the smallest user test that validates the hypothesis
- Prefer: paper prototype → clickable mockup → smoke test → A/B test

### 4. Design Studio (collaborative workshop)
- Duration: 90 min · Participants: PO + UX + Dev + Stakeholder
- Phase 1: Problem framing (20 min)
- Phase 2: Individual sketching (20 min)
- Phase 3: Presentation + vote (30 min)
- Phase 4: Solution synthesis (20 min)

### 5. Build → Measure → Learn loop
```
Hypothesis → Fast experiment → Data → Decision (pivot / persevere / stop)
```

## Integration into the Scrum sprint

| Event | Lean UX action |
|---|---|
| Backlog Refinement | Identify high-hypothesis US → MVE first |
| Sprint Planning | Reserve 20% of capacity for UX Discovery |
| Sprint Review | Present user learnings + metrics |
| Retrospective | Assess whether the hypotheses were confirmed |

## Typical deliverables
- Hypothesis sheet (Assumption Map)
- User-validated paper proto / Figma mockup
- Learning report (1 page max)
- US updated with measurable success criteria

## Anti-patterns to avoid
- ❌ Designing in isolation without real users
- ❌ Validating only with internal stakeholders
- ❌ Waiting for the "real" prototype before testing
- ❌ Confusing UX Research and Lean UX (not the same cadence)

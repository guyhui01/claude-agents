# Skill — Lean UX & Design Thinking intégré au sprint

> Certification : PSPO II · PSU-I
> Agent : AGENT-PO-SCRUM.md

## Objectif
Intégrer les pratiques Lean UX et Design Thinking dans le cycle Scrum pour réduire le gaspillage de développement et valider les hypothèses produit avant de coder.

## Quand utiliser ce skill
- Avant de rédiger une User Story sur une fonctionnalité incertaine
- Lors d'un Dual Track Discovery / Delivery
- Pour challenger des assumptions produit avec des données utilisateurs réelles

## Pratiques Lean UX à maîtriser

### 1. Problem Statement
```
[Utilisateur] a besoin d'une façon de [besoin/objectif]
parce que [insight — pourquoi ce besoin existe]
```

### 2. Hypothèse de valeur (Value Hypothesis)
```
Nous croyons que [fonctionnalité]
permettra à [utilisateur]
d'atteindre [résultat attendu]
Nous le saurons quand [métrique de validation]
```

### 3. Expérience Minimum Viable (MVE)
- Identifier le plus petit test utilisateur qui valide l'hypothèse
- Privilégier : prototype papier → maquette cliquable → smoke test → A/B test

### 4. Design Studio (atelier collaboratif)
- Durée : 90 min · Participants : PO + UX + Dev + Stakeholder
- Phase 1 : Problem framing (20 min)
- Phase 2 : Sketching individuel (20 min)
- Phase 3 : Présentation + vote (30 min)
- Phase 4 : Synthèse solution (20 min)

### 5. Boucle Build → Measure → Learn
```
Hypothèse → Expérience rapide → Données → Décision (pivot / persévérer / arrêter)
```

## Intégration dans le sprint Scrum

| Cérémonie | Action Lean UX |
|---|---|
| Backlog Refinement | Identifier les US à hypothèse forte → MVE d'abord |
| Sprint Planning | Réserver 20% de capacité UX pour Discovery |
| Sprint Review | Présenter apprentissages utilisateurs + métriques |
| Rétrospective | Évaluer si les hypothèses se sont confirmées |

## Livrables typiques
- Fiche hypothèse (Assumption Map)
- Proto papier / maquette Figma validée utilisateur
- Rapport d'apprentissage (1 page max)
- US mise à jour avec critères de succès mesurables

## Anti-patterns à éviter
- ❌ Designer en chambre sans utilisateurs réels
- ❌ Valider uniquement avec des stakeholders internes
- ❌ Attendre le "vrai" prototype avant de tester
- ❌ Confondre UX Research et Lean UX (pas le même rythme)
